# 文章の書き方チェック＆修正（下書き後・公開前）

textlint／`check:citations` とは**別ループ**です。機械校正のあと、エージェントまたは Kenta が記事を読み直し、契約どおりに直します。

## いつ走らせるか

1. Step C で `src/content/posts/vol-N.md` を書いた直後  
2. 人間レビュー・`git commit` の前  
3. 文体・束ね・口コミ1文まわりで「まだ粗い」と感じたとき  

```bash
npm run prose-review -- --vol N
# または
npm run prose-review -- src/content/posts/vol-N.md
```

このコマンドは **LLM を呼びません**。チェックリストを表示し、見つかれば禁則っぽい断片を警告するだけです。修正は人が（またはエージェントが本ファイルを読んで）行います。

## 正本との関係

| 層 | 役割 |
| :--- | :--- |
| 本ファイル＋ `scripts/draft-prompt.md` | **portable** の最低契約（見出し・口コミ1文・出典・声の禁止） |
| `npm run check:textlint` など | 表記・リンク・出典の**構造**ガード |
| 任意のローカル skill 補助 | 語尾の厚み・へッジの細かい見本（なくても本チェックは完走できる） |

## チェックリスト（上から順に）

対象ファイルを開き、各項を確認する。だめならその場で直す。

### A. メディアの声

- [ ] 広報の**まとめ／抜き出し列挙**になっていない（読み物の接続・フレームがある）
- [ ] 「要約しました」「投稿があります」「案内されています」など**要約口調／工程っぽい口**がない
- [ ] 地の文は**ですます調**（だ・であるを本文の基本にしない）
- [ ] 事実（日時・場所・料金）は断定。へッジ（ようです／思います／という声もあります）の**連打**がない

### B. 工程メタ・禁止フレーズ

- [ ] 編集手順の説明がない（禁則例: 近いものから拾う／優先して選んだ／候補からまとめる）
- [ ] 「試験下書き」「要確認」などのフッター免責がない
- [ ] 本文にパイプライン／抽出の話を書いていない

### C. 見出しと束ね

- [ ] 最初のピックアップだけ `#`。以降のピックアップと「直近」「今週のあきた」は `##`
- [ ] 傘見出し「ピックアップ」がない
- [ ] `## 直近のイベント情報` / `## 今週のあきた` の直下 `###` は **地域のみ**（県北 → 県央 → 県南）。**テーマを h3 にしない**
- [ ] 直近＝未来／今週のあきた＝過去。ピックアップとトピックが二重になっていない

### D. 口コミ（ある場合）

- [ ] 各口コミは **メディアの1文＋ oEmbed**（embed だけの列にしない）
- [ ] 本人宣伝だけ落とし、客の店紹介は残している
- [ ] 未確認の噂を事実にしていない
- [ ] 出典が embed ごとにある: `> 出典: 口コミ（Threads）` ＋ permalink

### E. 出典・画像

- [ ] 広報項も毎回フル出典（「同上」「同」「前掲」なし）
- [ ] 画像は `/images/kouhou/vol-N/…`（`data/` 直リンクなし）

### F. 直し方

1. だめな箇所を特定する（声／メタ／見出し／1文／出典）  
2. **同じ契約のまま**言い換える・削る・見出しを直す（契約を緩めない）  
3. 直し終わったらもう一度 A〜E を流す  
4. 問題なければ人間確認 → `npm run check:fast`（または `check`）→ commit  

## エージェント向け手順（短縮）

```
1. npm run prose-review -- --vol N
2. 本ファイルと対象 vol-N.md を読む
3. チェックリストで落ちた項だけ修正して上書き保存
4. 再度 prose-review（警告が残れば続ける）
5. STOP — 人間レビュー（自動 commit しない）
```
